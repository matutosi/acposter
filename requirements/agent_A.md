# 案A: 学術ポスター PDF 作成ツール設計案

見本 PDF (`acposter/poster.pdf`) を確認．A0 縦，上部に緑帯タイトル・著者，本文は緑の角丸枠見出し (OBJECTIVES/BACKGROUNDS/METHODS/RESULTS/CONCLUSIONS) を2段組で配置，画像・表・図を多用する構成．

## 1. 技術方式

- **既存2スキルと同じ設計思想を採用**: pandoc (md→HTML) + ヘッドレス Chrome (HTML→PDF 印刷) + CSS 印刷経路．LaTeX 不使用．
- 共通点: ps1 ラッパー + css + lua フィルタの3点構成，体裁ファイルはプロジェクト側で上書き可 (対象 md と同じディレクトリ → `build/` → スキル同梱の順で探索)，`type` ヘッダーで対象 md を判別 (`type: "学術ポスター"` 等)．
- 相違点: build-abstract-pdf は1ページ固定・build-slide-pdf は `# ` 区切りで複数ページ．**ポスターは常に1ページ**(A1/A0 の巨大な1枚紙)．よって lua フィルタの役割は「ページ分割」ではなく「見出し→BOX 変換・段組領域の割り付け」になる．

## 2. A1/A0 サイズの実現方法

- `@page { size: <幅> <高さ>; margin: ... }` に **mm 実寸**を直書き (A1 = 594mm×841mm，A0 = 841mm×1189mm)．Chrome の `--print-to-pdf` はカスタム用紙サイズを問題なく扱える．
- **フォントサイズは「A4 相当の可読性」を基準に逆算**する．A4 縦を基準ポイント (例: 本文 10.5pt) とし，A1 なら A4 の約 √2×2 ≈ 2.83 倍，A0 なら 4 倍を目安に `html { font-size: }` を用紙サイズで切り替える (`-Size A1`/`-Size A0` 引数で `@page` と `font-size` 基準値をセットで切り替えるテーブルを ps1 に持つ)．
- 見出し・本文・キャプションそれぞれの基準 pt を css の変数 (CSS `:root { --fs-base }` 等) で1箇所にまとめ，用紙サイズ切り替え時はこの変数だけ差し替える設計にする．
- 検算: 「A4 に縮小印刷しても文字が判読できるか」は，出力 PDF を Chrome で A4 相当に縮小レンダリングしたスクリーンショットで目視確認する運用ノートを SKILL.md に残す (自動化は今回は必須としない)．

## 3. 縦長・横長 (Landscape) の切り替え方法

- `@page` の `size` に `portrait`/`landscape` を付けるだけでは寸法が入れ替わらない実装差が Chrome にはあるため，**幅と高さを明示的に入れ替えた2値を css 側にテーブルで持つ**方式にする (`size: 841mm 1189mm` と `size: 1189mm 841mm` を `-Orientation portrait|landscape` で選択)．
- 段組の列幅・BOX 幅は `%` 指定にしておけば向きが変わっても組み替え不要．

## 4. 段組みの実装

- タイトル部 (帯) は `.title-band { column-count: 1; }` (もしくはそもそも `columns` 適用範囲外の独立ブロック)．
- 本文全体は `column-count: 2; column-gap: ...;` を基本とする CSS multi-column．
- **多段組・部分1段組を可能にする設計**:
  - ps1 引数 `-Columns 2` (既定2，3以上も可) で本文全体の `column-count` を差し替える．
  - md 側で `::: onecol ... :::` のような pandoc fenced-div 記法を用意し，lua フィルタでその div に `column-span: all` (CSS の `column-span` プロパティ) を付与するクラスに変換．これにより2段組の途中に「部分的に1段の全幅ブロック (大きな図・表など)」を差し込める．
  - 見本 PDF の下段 (SUMMARY of GOLF COURSE の表，Dominant species の画像列) はまさにこの「全幅ブロック」に該当する典型例．

## 5. 緑角丸枠見出し (BOX 見出し) の再現

- **`# ` 見出しごとに1つの BOX として扱う設計を採用** (build-slide-pdf の「`# ` = 1スライド」と同じ発想を，ポスターでは「`# ` = 1 BOX」に転用)．
- lua フィルタで `# 見出し` とその直後から次の `# ` (または `## `) までの内容を `<div class="box"><div class="box-title">見出し</div>...本文...</div>` にラップする．
- CSS で `.box { border: 3px solid #2e7d32; border-radius: 12px; }`，`.box-title { background: #2e7d32; color: #fff; border-radius: 8px; padding: ...; }` のような緑角丸見出しを再現．色・線幅は css 変数化し，プロジェクト側で上書き可能にする．
- BOX 自体は段組の中の1要素として `break-inside: avoid-column` を指定し，段の途中で BOX が分断されないようにする (Chrome の print で columns + break-inside の相性は要検証点として明記)．

## 6. 画像記法の扱いと lua フィルタの設計

- ユーザ原文の `[メモ](filename.png)` は pandoc 標準記法ではリンク (`<a>`) になる．**標準の `![caption](filename.png)` (画像) の書き間違いと判断して設計する**．根拠: 「画像を挿入する」という要件本文と噛み合うのはリンクでなく画像記法のみであり，事実として `[...]` は pandoc ではハイパーリンクにしかならない．
- ただし**保険として lua フィルタに「拡張子が画像 (.png/.jpg/.svg 等) の Link ノードは Image ノードとして扱う」変換を1つ入れておく**．これにより仮にユーザが今後も `[メモ](x.png)` 記法を使い続けても画像として出力され，事故を防げる (SKILL.md にはこの救済策があることと，正式には `![caption](...)` 推奨であることを明記する)．
- build-slide-pdf で踏んだ罠 (`p` に包まれると `max-height:100%` が効かず原寸で切れる) を踏まえ，**画像は必ず `div.fig > img` の形にする**同様の lua 処理を入れる．ポスターでは画像は BOX 内や全幅ブロック内に収まる必要があるため，`div.fig { max-width: 100%; }` `.fig img { max-width: 100%; height: auto; }` とし，スライドのような「残り高さいっぱい」ではなく「幅に収める」制約を基本にする (BOX は縦方向にはコンテンツに応じて伸びる想定のため)．
- 表・図が多いのが見本 PDF の特徴なので，pandoc の表変換 (パイプテーブル) はそのまま活用し，`table { font-size: 0.8em; }` 等を css に用意する．

## 7. ファイル構成案

- スキル名: **`build-poster-pdf`** (既存2つの命名規則 `build-*-pdf` に揃える)．
- 配置: `~/.claude/skills/build-poster-pdf/` (実体は `todo/.claude/user/skills/build-poster-pdf/`，3台共有)．

| ファイル | 役割 |
|---|---|
| `SKILL.md` | 使い方・YAML ヘッダーの約束・体裁の直し方 |
| `make_poster_pdf.ps1` | pandoc → Chrome 呼び出し，`-Size A1\|A0`・`-Orientation portrait\|landscape`・`-Columns N`・`-Css`・`-Lua`・`-KeepHtml` を受け付け，生成後に検算 |
| `poster.css` | `@page` の用紙サイズ表・列数・BOX の緑角丸見出し・画像/表の収め方・全幅ブロック (`column-span: all`) |
| `poster.lua` | ヘッダーから帯タイトル・著者行を生成，`# ` ごとに BOX へラップ，`::: onecol :::` を全幅クラスへ変換，画像の `div.fig` 化，`[..](img)` の画像救済 |

## 8. 出力後の検算項目

- **用紙寸法の実測**: 生成 PDF の MediaBox を読み取り，指定した A1/A0・向きと一致するか照合 (build-slide-pdf の「用紙の向き」検算と同じ手法を寸法照合に拡張)．
- **ページ数**: 常に1ページであることを確認 (2ページ以上になっていたら BOX か画像があふれている合図)．
- **フォント埋め込み**: 既存2スキルと同じく `/BaseFont` を正規表現で拾い，想定フォント名 (`-R`/`-B` の罠を踏まえた正しい名前) だけが埋め込まれているか確認．
- **段組崩れの検出**: 自動判定は難しいため，**BOX の矩形座標を中間 HTML 上で取得し，同じ段 (column) 内で BOX 同士が重なっていないか**を簡易チェックする補助スクリプトを用意する案 (必須ではなく `-CheckLayout` 相当のオプション扱い)．最低限は「ページ数が1に収まっているか」で崩れ (あふれ) を代理検知する．
- **画像解像度の粗さ検出**: A0 は原寸が大きいため，元画像の実ピクセル数が印刷サイズに対して不足していないか (dpi 目安 150 以上) を警告する簡易チェックを ps1 に入れる案 (既存2スキルにはない,ポスター特有の懸念点)．

## 9. 依存ツール一覧

- **pandoc** (既存2スキルと共用，追加インストール不要)
- **Chrome または Edge** (既存と共用)
- フォント: 既定で UD デジタル教科書体 N (共有システムフォント，追加不要)．タイトル帯の欧文表記が多い見本なので，英数字用に既存の欧文フォールバックで足りるか確認する程度で追加フォントは不要と判断．
- **それ以外は不要**．LaTeX・R・Node 系ライブラリ・画像処理ツールは導入しない．BOX 座標検算も Chrome の DevTools Protocol か中間 HTML の DOM 取得で済むため追加ツール不要．

## この案の要点 (3行以内)

既存2スキルと同一の pandoc+Chrome+CSS 経路を踏襲し，`# ` 見出し1つを緑角丸 BOX に変換する lua フィルタと，A1/A0 用紙サイズ・向き・列数を ps1 引数で切り替える css 変数設計を核とする．画像記法は `![caption](img)` を正式仕様としつつ `[メモ](img.png)` も画像として救済するフィルタを保険で入れる．依存ツールは pandoc・Chrome・既存フォントのみで増やさない．
