# 案E: 学術ポスター PDF 作成ツール設計 (開発コスト最小化・既存コード流用重視)

## 1. 技術方式

- 基本方針どおり **pandoc + ヘッドレス Chrome + CSS 印刷、LaTeX 不使用** を採用する。
- 既存2スキルとの共通点: ps1 ラッパー (対象 md 探索 → CSS/Lua 探索 → pandoc → Chrome 印刷 → 検算) の骨格をそのまま流用する。`make_abstract_pdf.ps1` の 130-189 行 (フォント/ページ数検算、Chrome 起動、書き込み完了待ちループ) は**ほぼ無改造で使い回せる**。
- 相違点: ポスターは「1枚もの・複数見出し枠・2段組」なので、`# ` 区切りでページを割る `slide.lua` の思想ではなく、**`# ` ごとに1つの緑角丸枠 (BOX) として本文内に配置**する思想 (abstract.lua の「ヘッダーから表題を組む」処理を流用しつつ、本文側は新規)。
- ページは**常に1枚 (1ページの PDF)**。Chrome の `--print-to-pdf` はそのまま使えるが、`@page size` を A0/A1 の実寸 mm に設定する点だけが新規。

## 2. A1/A0 サイズの実現方法

- `@page { size: 594mm 841mm; }` (A1 縦) のように **mm 実寸で直書き**する (`size: A1` という CSS キーワードは Chrome の対応が不安定なため、既存2スキルの流儀 (abstract.css も `size: A4` だが小さいので実は問題なし。ポスターは大判なのでキーワードに頼らず実寸で書く方が安全)。
- A0/A1 の切替えは `-Size A0` / `-Size A1` 引数で `@page` の値を差し替える (ps1 側で mm を計算、または2種の css を用意)。
- **フォントサイズの基準値**: `html { font-size: }` を絶対値 (pt) ではなく **A0 縦 (841×1189mm) を基準に本文 24-28pt 相当** に設定し、A1 はその 70.7% (√2 分の1、A系列の縮小比) を掛ける。既存スキルは `html { font-size: 10.5pt }` (abstract) / `36pt` (slide) という「基準1箇所を変えれば全体が連動」設計 (em 指定の徹底) を採っており、これを**そのまま踏襲**すれば A0→A1 切替えは基準フォントサイズ1行を変えるだけで済む。
- A4 相当の可読性は「検算」ではなく**設計時に固定**する: 見本 PDF (A0 相当と推定) の本文が概ね 5mm 角前後の字高であることから、本文 24pt・見出し (BOX タイトル) 32-36pt を初期値とし、**ユーザに実寸プリントで確認してもらう運用**にする (自動検算は困難、後述8)。

## 3. 縦長・横長 (Landscape) の切り替え方法

- `@page` の `size` の幅高を入れ替えるだけ。`-Orientation portrait|landscape` 引数を ps1 に持たせ、css をテンプレート文字列置換 (または2ファイル用意) で出し分ける。
- 見本は縦長のみなので、**MVP では縦長固定**でよい。Landscape は「できれば」要件であり、`@page` の1行を変えるだけで対応可能な設計にしておけば後回しで問題ない。

## 4. 段組みの実装

- CSS `columns` を使う。タイトル部 (`.title-block`) は `column-span: all` 相当 (実際には columns コンテナの外に置けば自然に1段)。
- 本文は `.body { columns: 2; column-gap: 10mm; }`。
- 多段・部分1段組は `-Columns 2` 引数 (既定2) と、md 側で `::: onecol` … `:::` (slide.css の `.small` と同じ書式感) を囲むと `column-span: all` になる div を lua フィルタで生成、という設計にする。
- **MVP では固定2段組のみ実装**し、多段・部分1段組は Div 属性 (`{.col1}` のような fenced div) の**受け皿だけ用意して実装は後回し**にする (要件に「できれば」と明記されており優先度低)。

## 5. 緑角丸枠見出し (BOX) の再現

- `# ` ごとに1つの `div.box` として扱う設計を採用する。**abstract.lua の `Pandoc(doc)` 関数の「ヘッダーからブロックを組み立てて差し込む」パターンをそのまま応用**し、新規 lua は「`# ` を区切りに `slide.lua` と同じ要領でブロックを集める」処理を書く (`slide.lua` 71-124行の分割ロジックがほぼそのまま使える。相違点は「ページに割る」のではなく「同じページ内の div として並べる」だけ)。
- CSS: `.box { border: 2px solid #2e7d32; border-radius: 12px; padding: 8mm; margin-bottom: 6mm; break-inside: avoid; }` + `.box > h1 { background: #2e7d32; color: #fff; border-radius: 8px; padding: 2mm 6mm; display: inline-block; margin: -14mm 0 4mm -2mm; }` のような「タイトルが枠を少しはみ出して乗る」見本の意匠を再現する。
- `break-inside: avoid` は 2段組の中で枠が段の境目で割れるのを防ぐ (Chrome の print では `page-break-inside: avoid` も併記が安全)。ただし2段組コンテナ内での `break-inside` は挙動が不安定なことがあるので、**崩れたら該当 box だけ手動で `{.col1}` (1段扱い) に逃がせる設計**にしておく。
- 色・角丸半径は変数化 (`:root { --box-color: #2e7d32; }`) し、学会ごとに色を変えられるようにする (abstract.css が学会ごとに上書き可能な設計を踏襲)。

## 6. 画像記法の扱い

- ユーザ原文の `[メモ](filename.png)` は Markdown 標準のリンク記法であり、画像記法ではない (`![alt](filename.png)` の書き間違いと判断)。**`![caption](filename.png)` を前提に設計する**。ただし保険として、`[任意の文字列](拡張子が画像の相対パス)` という誤記パターンをフィルタ側で検出し `Image` に読み替える救済も lua に1関数足しておく (コストは小さい)。
- 画像配置は **slide.lua/slide.css の `div.fig` パターンをそのまま流用**する。「画像だけの段落を `div.fig` に包み、中の `p` を外す (`is_figure` 関数、41-63行) 」というロジックと、「`.fig img { max-height: 100%; object-fit: contain }` (slide.css 70-79行)」という CSS は、ポスターの「画像・表・図を多用」という要件に**無改造で使い回せる**。
- 相違点は高さの基準: スライドは「スライド残り高さいっぱい」だが、ポスターの box 内画像は「box の残り高さ」または「明示的な `width: 100%`」に変える程度の差分。
- キャプションは `![caption](...)` の caption を出したいケースがあるので (要旨・スライドは alt を消しているが、ポスターの図は見本にキャプション文字列がある)、`-implicit_figures` を切らずに `figcaption` を出す分岐をオプション化する。

## 7. ファイル構成案

```
~/.claude/skills/build-poster-pdf/
  SKILL.md
  make_poster_pdf.ps1   # abstract/slide の ps1 を土台に流用 (探索・pandoc・Chrome・検算)
  poster.css            # @page 実寸・box 意匠・2段組・画像
  poster.lua            # #見出しごとの box 分割 (slide.luaの分割ロジック流用) + 画像div化 (slide.lua流用) + 表題ブロック (abstract.lua流用)
```

- 名前は `build-poster-pdf` (既存2スキルの命名規則 `build-<種別>-pdf` に揃える)。
- CSS/Lua 探索順 (md と同階層 → build/ → スキル同梱) も**そのまま踏襲**、`Resolve-Asset` 関数 (ps1 60-69行) は無改造で流用可能。

## 8. 出力後の検算項目

- **ページ数**: 常に1ページであることを検算 (既存の正規表現カウントをそのまま流用、`-ne 1` で警告)。
- **フォント埋め込み**: 既存の `/BaseFont` 正規表現抽出をそのまま流用。
- **用紙サイズ**: PDF の `/MediaBox` を読み、指定した A0/A1 の mm と一致するか (pt 換算、±1pt 許容) を検算する新規ロジックを追加 (既存にない項目だが、`/BaseFont` 抽出と同じ正規表現方式で数行の追加で済む)。
- **段組み崩れの検出**: 自動検出は難しいため、**MVP では「中間 HTML を Chrome で開いて目視確認」を運用手順として明記するに留める** (`-KeepHtml` フラグを既存スキルから流用)。将来的に余裕があれば、box の `getBoundingClientRect()` を Chrome の `--dump-dom` 等で取得し box 同士の矩形重なりを検出する仕組みを検討するが、初版には入れない。
- **box 数の検算**: `# ` の数と生成された `div.box` の数が一致するか (pandoc の中間 HTML を正規表現で数える) を追加。既存にない項目だが実装コストは低く、box 抜け落ちの早期発見に有効なので**初版に含める**。

## 9. 依存ツール一覧

- pandoc、Chrome (または Edge)、フォント (UD デジタル教科書体 N 等、既存と同じ Windows 標準フォント) 以外は **不要**。
- 大判 (A0/A1) の PDF/A や色空間変換などの印刷所向け後処理は、要件に明記が無いので**スコープ外** (必要になれば別途 Ghostscript 等の検討だが、初版では入れない)。

## MVP の切り方 (最重要)

**第1版に入れる**: 縦長・A0固定 (A1はフォント基準値の1行変更で足りるので合わせて対応)、box (`# ` 単位の緑角丸枠、`slide.lua`+`abstract.lua` の合成流用)、固定2段組 (タイトルのみ1段)、`div.fig` 画像配置 (`slide.css`/`slide.lua` 無改造流用)、ページ数・フォント・用紙サイズ・box数の検算。

**後回しにする**: Landscape 切替え (CSS 1行差分なので後からでも安い)、多段・部分1段組の完全なオプション化 (受け皿の fenced div 構文だけ用意)、段組み崩れの自動検出 (目視+KeepHtml運用で代替)、`[メモ](...)` 誤記の自動救済 (実害が出たら追加)。

## この案の要点 (3行以内)

既存2スキルの ps1/検算ロジックはほぼ無改造で流用でき、box (角丸枠見出し) は abstract.lua のヘッダー組立てと slide.lua の `# ` 分割・`div.fig` 画像処理を合成すれば大半が書ける。A0/A1 は `@page` 実寸と基準フォントサイズの1変数化で切替え可能にし、Landscape・多段組・段組崩れ自動検出は要件上「できれば」枠なので初版から意図的に外す。画像記法は `![caption](...)` 前提で設計し、原文の `[メモ](...)` は誤記として扱う旨を明記する。
