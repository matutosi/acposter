# ポスター作成ツール設計案 (案B)

見本 PDF を確認した．緑帯 (濃緑) の表題・著者ブロックが最上部を1段組で横断し，本文は BACKGROUNDS/OBJECTIVES/METHODS/RESULTS/CONCLUSIONS/SUMMARY/Dominant species 等の「緑の角丸枠見出しボックス」が左右2列に**非対称の高さ**で並ぶ (RESULTS の表・散布図ブロックは他より縦に長い)．つまり自動流し込みの2段組ではなく，**ブロックごとに高さの違う「敷き詰め」レイアウト**である点が最大の特徴．

## 1. 技術方式

- **pandoc + ヘッドレス Chrome + CSS 印刷**を踏襲する．LaTeX 不使用．
- `build-slide-pdf` に近い設計 (`# ` 区切りで1ブロック) を採るが，スライドの「1見出し=1ページ」ではなく「**1見出し=1ボックス (同一ページ内に配置)**」という点が本質的に異なるので，共通コードの流用より**構造の考え方の流用**にとどめる．
- 出力は**1ページ物**(ポスターは通常1枚)．ページ送りの概念がないため，`build-abstract-pdf`/`build-slide-pdf` が前提とする「複数ページ・ページ数検算」はそのままでは使えず，**「1ページに収まったか」の検算**に置き換える (詳細は8)．

## 2. A1/A0 サイズの実現

- `@page { size: 594mm 841mm; }` (A1 縦) / `1189mm 841mm` (A0) を CSS に直書きする．pandoc 側は関与しない．
- **基準フォントサイズは mm 起点で決める** (`pt`/`px` は Chrome の DPI 変換で誤差が出やすい)．例: 本文 `font-size: 7mm` (A1 縦) 前後を既定値とし，A4 換算で判読できるかは「**A1 の実寸を 1/√8 に縮小して A4 相当**」の考え方で逆算する (A1 面積は A4 の8倍なので，A1 上で目視 3-5m 相当の文字サイズ = A4 縮小プレビューで概ね本文 8-9pt 相当になるよう校正)．
- サイズ切替は `-Size A1|A0` 引数で `@page` の `size` と基準 `font-size`(mm) を連動して変える (A0 は A1 の√2倍分，フォントも同率で拡大)．**A4 は検版用**として同じ CSS で `size: A4` に差し替えられるようにし，「A4 出力→拡大率を頭で割り戻して読みやすさを確認する」運用を可能にする (実物大出力の前に必ず一度 A4 検版を挟む，をスキルの使い方に明記)．

## 3. 縦長・横長 (Landscape) の切替

- `-Orientation Portrait|Landscape` 引数で `@page` の向きと，ルート `<body>` の `width/height` を入れ替える．
- レイアウトは 5. の CSS Grid で「行×列」を定義するため，向きが変わっても**グリッドの `grid-template-columns`/`rows` の定義を差し替えるだけ**で対応でき，本文側 md の書き換えは不要にする (向きは体裁ファイル側の責務，原稿側の責務にしない).

## 4. 段組みの実装 — CSS Grid を主軸に据える (案Bの重点)

**CSS columns (自動流し込み) は不採用**．理由: ポスターは見本のとおり「枠ごとに独立した箱」がタイトル下に敷き詰められる構成で，`columns` は同一ブロック内でテキストが段をまたいで自動的に流れる用途 (新聞のコラム) に向くが，**ボックス単位で高さが不揃いな配置とは相性が悪い**(あふれ・段間のずれが生じやすいという課題そのもの).

- **`display: grid` でポスター全体を骨格化する**．
  - タイトル行: `grid-template-areas` の最上段に `"title title"` を1行だけ占有させ，1段組を保証する．
  - 本文: 既定は2列 `grid-template-columns: 1fr 1fr`，各見出しボックスは `grid-column: auto` で自然に列内へ積む (= 列内では **flow (通常のブロック積み上げ)**，列をまたぐ自動流し込みはさせない)．
  - 多段組は `grid-template-columns: repeat(N, 1fr)` の N を引数で変える (`-Columns 2|3|4`)．
  - 部分的な1段組 (見本でいう「Dominant species」「Other species」の下段2枠が横に広い等) は，見出し (`# `) の直後の**属性記法**で個別に `grid-column: span 2` のようにまたがせる. 例: `# CONCLUSIONS {.span2}` → その枠だけ2列分を占有する CSS クラスをマッピングする lua フィルタで処理する．
- **列内の縦の敷き詰めは各列を `display: flex; flex-direction: column; gap: …mm` とし，ボックスの高さは中身に応じて自然に伸びる(= 見本の非対称な高さを素直に再現)**．固定 `height` は指定しない (指定すると中身があふれて切れる恒常的な罠になるため；かわりに 8. で「はみ出し」を検算で検出する).
- 列の順序保証: HTML の出現順そのままを左列→右列と交互に配るか，見出しに `{.col1}`/`{.col2}` を明示できるようにするかは選べるようにする．**既定は「出現順に列0,1,0,1…と交互配置」**とし，見本のように意図した配置 (OBJECTIVES→左上, CONCLUSIONS→右上 と決め打ちたい場合) は `{.col1}` 等の属性で上書きできる設計にする．

## 5. 緑角丸枠見出し (BOX見出し) の再現

- `# 見出し文字列` を**1ボックスの開始区切り**として lua フィルタで検出し，見出し以降 (次の `# ` または文書末) までの内容を `<div class="box"><h2>見出し</h2>...本文...</div>` にまとめる (`build-slide-pdf` の `#` 区切りロジックを流用できる — 違いは「ページ分割」ではなく「div でラップ」).
- CSS: `.box { border: 3px solid #2e7d32; border-radius: 14px; padding: …mm; }`, 見出し `.box h2` は緑地・白文字の角丸バナー (`background: #2e7d32; border-radius: 8px; padding: …; margin: -見出し分だけ上にはみ出す` で見本の「枠の上端に食い込むタイトルバー」を再現する: `position: relative; top: -Xmm;` または `margin-top: -Xmm` で軽く重ねる).
- 色・線太さ・角丸半径は CSS 変数化 (`--box-color`, `--box-radius` 等) してプロジェクト側 CSS で上書き可能にする．

## 6. 画像記法の扱い

- ユーザ原文の `[メモ](filename.png)` は**リンク記法** (`[text](url)`) であり，画像記法は `![alt](filename.png)` である．**書き間違いと判断し，標準の `![caption](file.png)` を前提に設計する**．ただし lua フィルタ側で `[任意の文字列](*.png|*.jpg|*.jpeg)` のような**画像拡張子を持つリンク**を検出したら画像として救済変換する保険を入れる (ユーザが今後も書き間違える可能性を潰す)．
- `build-slide-pdf` で踏んだ罠 (`p > img` だと `max-height:100%` が効かず原寸表示ではみ出す) を踏まえ，**`div.fig > img` 構造を最初から採用**する (lua フィルタで `p` を剥がす処理を最初から入れておく．後から踏み直さない).
- ポスターは画像を多用し，かつボックスの高さが可変 (4. で `height` 固定を避けた) なので，画像は `max-width: 100%; height: auto;` を基本にし，**「残り高さいっぱいに収める」固定ロジックはボックス側には使わない**(ボックスの高さが画像に従って伸びる方が破綻しにくい)．複数画像を横並びにしたいときは `::: figrow` のような div 記法 (`build-book-pdf` の `figpair` に近い) を用意し，`display: flex; gap:` で横並びにする．

## 7. ファイル構成案

```
build-poster-pdf/
├── SKILL.md
├── make_poster_pdf.ps1   # pandoc→Chrome 呼び出し、-Size/-Orientation/-Columns 引数、はみ出し検算
├── poster.css            # @page(A0/A1)、Grid骨格、box見出し、画像収め方
└── poster.lua            # YAMLヘッダ→タイトル帯、#見出し→div.box、{.span2}等属性→grid-column、pの除去
```

- スキル名: `build-poster-pdf` (既存2スキルの命名規則 `build-<種別>-pdf` に合わせる)．
- 体裁ファイルの探索順は既存2スキルと同じ「対象 md と同じディレクトリ → build/ → スキル同梱」を踏襲し，学会・研究室ごとの色替え等をプロジェクト側で上書き可能にする．

## 8. 出力後の検算項目

ポスターはページ数の概念がほぼ意味を持たない (1枚物) ため，既存2スキルの「ページ数照合」とは別の検算に置き換える．

- **ページ数 = 1** であることの確認 (2ページ目ができていたら、どこかの内容が `@page` サイズを超えてあふれている強いシグナル).
- **用紙サイズ・向きが指定どおりか** (PDF のメディアボックスを検算．既存スキル同様の手法).
- **フォント埋め込みの確認** (既存2スキルと同じ `/BaseFont` 検算).
- **段組み崩れの検出** (案Bの重点，新規): 中間 HTML を Chrome の無ヘッド DevTools 経由 (`--dump-dom` や puppeteer 相当ではなく，pandoc/Chrome だけで完結させたいので) もしくは簡易に **各 `.box` の `getBoundingClientRect()` をヘッドレス Chrome の `--print-to-pdf` 前に JS 実行させて座標をログ出力**し，
  - いずれかの `.box` の下端が `@page` の版面高さを超えていないか (はみ出し)
  - 隣接する `.box` 同士が重なっていないか (Grid の意図せぬオーバーラップ)
  を ps1 側で機械的に判定し，超過があれば「どの見出しがあふれているか」を名指しで警告する．**これは build-slide-pdf の `overflow:hidden` で切って終わりにする方式ではなく，ポスターは1枚しかやり直しが利かないため「切らずに警告する」方針**にする (誤って重要な結果が見えなくなるのを防ぐ).

## 依存ツール一覧

- pandoc, Chrome (または Edge) — 既存2スキルと共通．**追加は不要**．
- フォント: 日本語混在時は既存2スキルと同じ UD デジタル教科書体 N を既定候補にするが，学会要旨と違い英語ポスターも多いので既定は指定なし (プロジェクト CSS で `font-family` を上書き).
- 座標検算のための JS 実行は Chrome の `--headless --dump-dom` や既存の Chrome 呼び出しの延長で足りるため，**新規ツール追加は不要**．
- **結論: pandoc・Chrome・フォント以外に追加で必要なツールはない**．

## この案の要点 (3行以内)

CSS columns の自動流し込みではなく，**CSS Grid で列骨格を作り，各見出しボックスは列内で自然に高さが伸びる「積み上げ」**にすることで，ポスター特有の不揃いな箱の敷き詰めを崩れなく再現する．A0/A1 は `@page` の mm 指定とフォント基準の連動拡大で対応し，はみ出し・重なりは座標ログで機械的に検算して警告する (切り捨てない)．依存ツールは pandoc/Chrome のみで既存2スキルの構成 (ps1+css+lua) を踏襲する．
