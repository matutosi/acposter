# build-poster-pdf 要件定義・方針決定 (2026-08-29)

5エージェント (案A〜案E，各案の全文は同ディレクトリの `agent_A.md`〜`agent_E.md`) が
独立に検討した結果と，それを踏まえてユーザが確定した方針．

## 全案が一致した点 (無条件で採用)

- **技術方式**: pandoc + ヘッドレス Chrome + CSS 印刷経路．**LaTeX 不使用**．
  `build-abstract-pdf`・`build-slide-pdf` と同じ「ps1 ラッパー + css + lua フィルタ」の
  3点構成，体裁ファイルの探索順 (md と同階層 → `build/` → スキル同梱) を踏襲する．
- **画像記法**: ユーザ原文の `[メモ](filename.png)` は pandoc 標準ではリンクにしかならないため，
  `![caption](filename.png)` (画像記法) の書き間違いと判断．正式には `![...]` を使う前提で設計し，
  拡張子が画像のリンクは自動で画像として救済する lua フィルタを保険で入れる．
- **箱 (BOX) 見出し**: `# ` 見出し1つ = 1つの緑角丸枠．lua フィルタで `div.box` にラップする．
- **画像配置の罠**: `build-slide-pdf` (slide.lua) が踏んだ「`p` に包むと `img` の `max-height`/
  `max-width` が効かない」罠を踏まえ，画像だけの段落は `div.fig > img` にする (`p` を挟まない)．
- **依存ツール**: pandoc・Chrome (または Edge)・既存の UD デジタル教科書体 N 以外は追加しない．
- **ファイル構成・命名**: `build-poster-pdf` (`build-<種別>-pdf` の命名規則)．
  `SKILL.md` / `make_poster_pdf.ps1` / `poster.css` / `poster.lua` の4点．

## 分かれた論点とユーザの決定

### 論点1: 段組みの実装方式

- 案A/C/E: CSS `columns` (自動流し込み)．シンプルだが，見本 PDF のような
  「箱の高さが不揃い・配置が非対称 (CONCLUSIONS が右列先頭など)」の再現は苦手．
- 案B/D: CSS Grid．列内で箱が自然に積み上がる形にでき，見本の非対称配置に近い．
  案D はさらに YAML `layout:` (見出し名の行列) で配置を明示できる二層構造を提案．

**決定: 1 (CSS Grid + layout 指定)**．ただし実装では，
`layout:` が**無いとき**は CSS `columns` による段組み流し込み (新聞調)，
`layout:` が**あるとき**だけ CSS Grid に切り替える**ハイブリッド方式**を採用した
(案A/C/E の「シンプルな既定」と案B/D の「柔軟な明示配置」の両立)．

### 論点2: 初版 (MVP) の作り込み範囲

- 案E: 縦長・box・画像・基本検算のみを初版に入れ，Landscape・多段組・部分1段組・layout 指定は
  「できれば」要件なので後回し (受け皿だけ用意)．既存スキルのコードをほぼ無改造で流用．
- 他案: 要件の「できれば」も含め，最初から引数で切り替え可能にする．

**決定: 1 (MVP優先)**．ただし実装コストが小さいものは MVP に含めた
(Landscape・A0/A1 切替え・`layout:` による Grid 配置・`{.full}` による部分全幅は
CSS 変数/属性1つで実現できるため含めた．自動段組み崩れ検出だけは論点3のとおり見送り)．

### 論点3: 段組み崩れ (箱のはみ出し・重なり) の検出

- 案B/C/D: 中間 HTML の座標を Chrome で取得し，はみ出し・重なりを自動検算して警告する．
- 案E: 初版では目視 + `-KeepHtml` 運用に留め，自動検出は後回し．

**決定: 1 (目視 + KeepHtml 運用)**．初版の検算は「ページ数=1・用紙実寸・箱の数・
フォント埋め込み」の機械検算に留め，座標ベースのはみ出し・重なり検出は入れない．
