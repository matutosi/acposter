# 学術ポスターの PDF ビルド (Chrome + CSS 経路)

ポスターの md 1本を **A0/A1・1枚**の PDF に組む。**LaTeX を使わず、HTML + CSS を Chrome の
印刷機能で PDF 化**する。`build-abstract-pdf`・`build-slide-pdf` と同じ設計 (pandoc→Chrome，
ps1+css+lua の3点構成，体裁ファイルはプロジェクト側で上書き可) を踏襲する。

- **A4 1枚の学会要旨**は `build-abstract-pdf`，**投影資料 (スライド)** は `build-slide-pdf`，
  **書籍・長い原稿**は `build-book-pdf`．
- 既存の R/ggplot2 製 `ggposter` とは別系統．どちらを使うかは案件ごとに選ぶ．

**現在は `acposter` プロジェクト専用のスキル** (`acposter/.claude/skills/build-poster-pdf/`)
として開発中。**指示があるまでは** `~/.claude/skills/` (3台共有のユーザースキル) へは
上げず，`acposter` の git リポジトリだけで版管理する (2026-08-29 ユーザ指示)。

## 前提ツール

- **pandoc** (Markdown → HTML)
- **Chrome** (無ければ Edge/Chromium。HTML → PDF の印刷に使う)
- **pwsh** (PowerShell 7+。Windows/Mac/Linux いずれにも入る)
- フォント **UD デジタル 教科書体 N** (Windows 10/11 に標準で入っている)。
  無いとき (Mac/Linux) は Hiragino Sans → Noto Sans CJK JP → IPAGothic → 汎用 sans-serif の
  順に探す (`poster.css` の `body` の `font-family`)。**体裁は Windows と完全には一致しない**。

TeX Live も R も要らない。どれかが無ければスクリプトがエラーで知らせる。

**Mac/Linux でも動く** (2026-08-29 対応)。ブラウザは OS ごとの既定の場所
(Mac: `/Applications/Google Chrome.app/...` 等) と，見つからなければ PATH 上の
コマンド名 (`google-chrome`・`chromium`・`chromium-browser` 等) の両方で探す。
フォントは上記のとおり自動でフォールバックするが，**Windows の見た目 (UD デジタル教科書体) を
そのまま再現するわけではない**。同じ設計の `build-abstract-pdf`・`build-slide-pdf`
(ユーザースキル側) は今回は対応していない (このプロジェクトのスコープ外)。

## 使い方

ポスターの md があるディレクトリで実行する。

```powershell
pwsh -File .claude/skills/build-poster-pdf/make_poster_pdf.ps1
```

| 引数 | 役割 |
|---|---|
| `-Md` | 対象の md。省略すると **ヘッダーの `type`** を見て選ぶ (下記) |
| `-Pdf` | 出力名。既定は `<md の基幹名>.pdf` |
| `-Size A0\|A1` | 用紙サイズ (既定 `A0`) |
| `-Orientation portrait\|landscape` | 向き (既定 `portrait`＝縦長) |
| `-Columns N` | **`layout:` 未指定のとき**の段数 (既定 `2`)。`layout:` を書けば列数はそちらが決める |
| `-FontSize` | 基準文字サイズを直接指定 (既定は `-Size` ごとの目安値。**A4 に印刷して読みにくければ上げる**) |
| `-KeepHtml` | 中間 HTML (`<基幹名>.tmp.html`) を残す。段組みの崩れを目視で確かめるときに使う |
| `-Css` / `-Lua` | 体裁ファイルを明示する |

**対象の md は名前では決めない**。ディレクトリの md を読み、ヘッダーの `type` が
`学術ポスター` / `ポスター` のものを選ぶ。該当が複数あれば `-Md` で指定する。

実行すると最後に **ページ数 (常に1のはず)・用紙実寸・箱の数・埋め込みフォント** を表示する。
ページ数が1を超えていたら、どこかの箱・画像・表が用紙からあふれている合図。

## md の書き方の約束

```yaml
---
title: "長期存続ゴルフ場における草地性種の多様性と管理との関係"
author: ["松村 俊和", "橋本 佳延", "澤田 佳宏"]
institute: ["甲南女子大学", "兵庫県立人と自然の博物館", "淡路景観園芸学校・兵庫県立大学"]
type: "学術ポスター"
note: "※本研究はJSPS科研費 15K07833 の助成を受けた"
---
```

| キー | 役割 |
|---|---|
| `title` | **表題**。緑地の表題帯の中央に大きく出る |
| `author` | 氏名。1人でもリストでも良い |
| `institute` | 所属。`affiliation` でも受ける。氏名と所属は `abstract` と同じ「氏名(所属)」の形に組み立てる |
| `type` | **これを見て処理するか決める**。`学術ポスター` か `ポスター` のときだけ通す |
| `note` | 表題帯の下に小さく出す注記 (謝辞・科研費番号など)。省略可 |
| `date` | **読み飛ばす** (ポスターでは使わない)。書いてあっても PDF には出ない |
| `layout` | 箱の配置を明示したいときだけ書く (下記「箱の配置」) |

本文の書き方は次のとおり。

- **`# 見出し` が1つの箱**(緑角丸枠)になる。見出しの文字列がそのまま箱の表題になる。
  `# ` より前に書いた内容は捨てられる (表題帯はヘッダーから自動生成するため)。
- 画像は標準の **`![キャプション](file.png)`** で書く。**`[メモ](file.png)` のような
  `!` の付け忘れ**は、拡張子が画像 (`.png`/`.jpg`/`.jpeg`/`.gif`/`.svg`/`.webp`) であれば
  自動で画像として救済される (保険。正式には `![...]` を使う)。
- 画像を横に並べたいときは `::: row` … `:::` で囲む。**画像どうしは空行で区切る**
  (空行が無いと1つの段落・1つの箱にまとまり，横並びにならない)。
- **画像の高さは既定で画面高さの30% (`--fig-max-h: 30vh`) までに抑える**。
  箱は中身に応じて自然に伸びる (固定 height なし) ので，これが無いと大きな画像1枚だけで
  箱が伸びきり，後続の箱がページからあふれる (2026-08-29 のフルコンテンツ検証で発見)。
  意図して大きく見せたいときは，プロジェクト側 `poster.css` の `:root` の
  `--fig-max-h` を上書きする (箱ごとの個別上書きは今のところできない)。
- 箇条書きは `- `。表はふつうの pandoc の表記法 (パイプテーブル) が使える。
- 説明文とコード例 (` ``` ` で囲む) を混ぜて書ける。コードは折り返して箱の幅に収まる。
- `<!-- ... -->` の中は PDF に出ない。**採らなかった素材の置き場**に使える。

## 箱の配置 (`layout`) — 省略してよい

**省略すると**、`# ` の出現順に **段組み流し込み** (新聞調。左列を上から埋め，あふれたら右列へ)
になる。まずはこれで書き始めるのがよい。

**見本のように配置を細かく決めたい**ときだけ、ヘッダーに `layout` を足す。
1行が Grid の1行、行の中の要素数がその行の列分割になる (1個だけなら全幅)。
同じ見出し名を複数行に書くと、その行数ぶん縦に結合される (長方形になるように書く)。

```yaml
layout:
  - [OBJECTIVES, CONCLUSIONS]
  - [BACKGROUNDS, RESULTS]
  - [METHODS, RESULTS]
  - [SUMMARY]
```

- `layout` の見出し名は、**本文の `# ` と一字一句 (空白の量以外は) 揃える**。
  揃っていない・本文にあるのに `layout` に無い見出しがあると、pandoc がエラーで止まる
  (取りこぼしたまま PDF ができてしまう事故を防ぐため)。
- `layout` を書いた時点で `-Columns` は無視される (列数は `layout` の行の最大要素数で決まる)。

## 段組みの途中で1段組みにしたい箱 (`layout` を使わないとき)

`layout` を使わず流し込みのままにしつつ、特定の箱だけ全幅にしたいときは
見出しに `{.full}` を付ける。

```markdown
# SUMMARY of GOLF COURSE {.full}
```

## 用紙サイズと文字の大きさ

- `-Size A0`(既定)/`-Size A1` と `-Orientation portrait`(既定)/`-Orientation landscape` で
  `@page` の実寸 (mm) を切り替える。
- 基準の文字サイズは `-Size` ごとの目安値 (A0=26pt・A1=18pt) を使う。
  **「A4 に印刷しても読める」かどうかは自動検算していない**。実物大で試し刷りするか、
  Chrome で PDF を A4 相当に縮小表示して目視で確かめる運用にする。読みにくければ
  `-FontSize 30pt` のように直接上げる。

## 体裁ファイルの探し方 (プロジェクト側で上書きできる)

`poster.css` と `poster.lua` を、次の順で探して**最初に見つかったもの**を使う。

1. 対象 md と同じディレクトリ
2. その下の `build/`
3. **スキル同梱** (`acposter/.claude/skills/build-poster-pdf/`)

学会・研究室ごとに色 (`--box-color`・`--title-bg`) を変えたいときは、
プロジェクトに `poster.css` を置いて `:root` の値だけ上書きすればよい。

## 段組み崩れの確かめ方 (自動検出はしていない)

初版では「箱がページからあふれていないか」「段組みが重なっていないか」の**自動検出はしない**
(方針として、まずは目視 + `-KeepHtml` 運用に留める)。

- `-KeepHtml` を付けて実行し、`<基幹名>.tmp.html` を Chrome で直接開いて確かめる。
- ページ数が1を超えていたら、内容が用紙サイズを超えてあふれている強いシグナル。
- 崩れる箱だけ `{.full}` を外す／`layout` の行を組み替える／`-FontSize` を下げる、で調整する。

## 中身

| ファイル | 役割 |
|---|---|
| `make_poster_pdf.ps1` | pandoc → Chrome の呼び出し。用紙サイズ・段数・文字サイズを差し込み、ページ数・用紙実寸・箱の数・フォントを検算する |
| `poster.css` | 体裁 (@page の既定値・表題帯・緑角丸枠の箱・段組み流し込み/Grid・画像/表) |
| `poster.lua` | ヘッダーから表題帯を組み立て、`# ` ごとに箱へ分割し、`layout` があれば Grid 配置に変換、画像の `div.fig` 化、`[..](img)` の画像救済 |
