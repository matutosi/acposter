# 学術ポスターの PDF ビルド (Chrome + CSS 経路)

ポスターの md 1本を **A0/A1・1枚**の PDF に組む。**LaTeX を使わず、HTML + CSS を Chrome の
印刷機能で PDF 化**する。`build-abstract-pdf`・`build-slide-pdf` と同じ設計 (pandoc→Chrome，
ps1+css+lua の3点構成，体裁ファイルはプロジェクト側で上書き可) を踏襲する。

- **A4 1枚の学会要旨**は `build-abstract-pdf`，**投影資料 (スライド)** は `build-slide-pdf`，
  **書籍・長い原稿**は `build-book-pdf`．
- 既存の R/ggplot2 製 `ggposter` とは別系統．どちらを使うかは案件ごとに選ぶ．

**現在は `acposter` プロジェクト専用のスキル** (`acposter/.claude/skills/build-poster-pdf/`)
として開発中。**指示があるまでは** `~/.claude/skills/` (3台共有のユーザースキル) へは
上げず，`acposter` の git リポジトリだけで版管理する (2026-08-29 ユーザ指示)。

## 前提ツール

- **pandoc** (Markdown → HTML)
- **Chrome** (無ければ Edge/Chromium。HTML → PDF の印刷に使う)
- **pwsh** (PowerShell 7+。Windows/Mac/Linux いずれにも入る)
- フォント **UD デジタル 教科書体 N** (Windows 10/11 に標準で入っている)。
  無いとき (Mac/Linux) は Hiragino Sans → Noto Sans CJK JP → IPAGothic → 汎用 sans-serif の
  順に探す (`poster.css` の `body` の `font-family`)。**体裁は Windows と完全には一致しない**。

TeX Live も R も要らない。どれかが無ければスクリプトがエラーで知らせる。

**Mac/Linux でも動く** (2026-08-29 対応)。ブラウザは OS ごとの既定の場所
(Mac: `/Applications/Google Chrome.app/...` 等) と，見つからなければ PATH 上の
コマンド名 (`google-chrome`・`chromium`・`chromium-browser` 等) の両方で探す。
フォントは上記のとおり自動でフォールバックするが，**Windows の見た目 (UD デジタル教科書体) を
そのまま再現するわけではない**。同じ設計の `build-abstract-pdf`・`build-slide-pdf`
(ユーザースキル側) は今回は対応していない (このプロジェクトのスコープ外)。

## 使い方

ポスターの md があるディレクトリで実行する。

```powershell
pwsh -File .claude/skills/build-poster-pdf/make_poster_pdf.ps1
```

| 引数 | 役割 |
|---|---|
| `-Md` | 対象の md。省略すると **ヘッダーの `type`** を見て選ぶ (下記) |
| `-Pdf` | 出力名。既定は `<md の基幹名>.pdf` |
| `-Size A0\|A1` | 用紙サイズ (既定 `A0`)。ヘッダーの `paper` でも書ける |
| `-Orientation portrait\|landscape` | 向き (既定 `portrait`＝縦長)。ヘッダーの `orientation` でも書ける |
| `-Columns N` | **`layout:`・`grid:` 未指定のとき**の段数 (既定 `2`)。どちらかを書けば列数はそちらが決める。ヘッダーの `columns`/`cols` でも書ける |
| `-FontSize` | 基準文字サイズを直接指定 (既定は `-Size` ごとの目安値。**A4 に印刷して読みにくければ上げる**)。ヘッダーの `font-size` でも書ける |
| `-Font` | 書体 (`"Yu Gothic"` など)。ヘッダーの `font` でも書ける。**並びの先頭だけが差し替わり**、Mac/Linux 用のフォールバックは残る |
| `-Accent` | 差し色 (`"#0b4f9e"`・`navy` など)。ヘッダーの `accent` でも書ける。**枠・見出し帯・表題帯がまとめて変わる** (`--box-color` と `--title-bg`) |
| `-KeepHtml` | 中間 HTML (`<基幹名>.tmp.html`) を残す。段組みの崩れを目視で確かめるときに使う |
| `-Css` / `-Lua` | 体裁ファイルを明示する |

**対象の md は名前では決めない**。ディレクトリの md を読み、ヘッダーの `type` が
`学術ポスター` / `ポスター` のものを選ぶ。該当が複数あれば `-Md` で指定する。

実行すると最後に **ページ数 (常に1のはず)・用紙実寸・箱の数・埋め込みフォント** を表示する。
ページ数が1を超えていたら、どこかの箱・画像・表が用紙からあふれている合図。

## md の書き方の約束

```yaml
---
title: "長期存続ゴルフ場における草地性種の多様性と管理との関係"
subtitle: "全国24コースの植生調査から"
author: ["松村 俊和", "橋本 佳延", "澤田 佳宏"]
institute: ["甲南女子大学", "兵庫県立人と自然の博物館", "淡路景観園芸学校・兵庫県立大学"]
type: "学術ポスター"
note: "※本研究はJSPS科研費 15K07833 の助成を受けた"
---
```

| キー | 役割 |
|---|---|
| `title` | **表題**。緑地の表題帯の中央に大きく出る |
| `subtitle` | **副題**。表題のすぐ下に一回り小さく出る。省略可 |
| `author` | 氏名。1人でもリストでも良い |
| `institute` | 所属。`affiliation` でも受ける。氏名と所属は `abstract` と同じ「氏名(所属)」の形に組み立てる |
| `type` | **これを見て処理するか決める**。`学術ポスター` か `ポスター` のときだけ通す |
| `note` | 表題帯の下に小さく出す注記 (謝辞・科研費番号など)。省略可 |
| `logo` | **ロゴ画像**のパス (md からの相対パス)。表題帯の右端に縦中央で入る。リストで複数書ける。`logos` でも受ける。省略可 |
| `accent` | **差し色**。枠・見出し帯・表題帯をまとめて変える (`#0b4f9e`・`navy` など)。`-Accent` と同じ |
| `date` | **読み飛ばす** (ポスターでは使わない)。書いてあっても PDF には出ない |
| `layout` | 箱の配置を**見た目どおりの行列**で書きたいときだけ (下記「箱の配置 (`layout`)」) |
| `grid` | 箱の配置を**座標 (x/y/w/h)** で書きたいときだけ (下記「箱の配置を座標で決める」)。`layout` より優先 (両方あると警告) |
| `paper` | 用紙 (`A0`/`A1`)。`-Size` と同じ |
| `orientation` | 向き (`portrait`/`landscape`)。`-Orientation` と同じ |
| `columns` | 段数。`cols` でも受ける。`-Columns` と同じ |
| `font-size` | 基準文字サイズ (`30pt` など)。`font_size` でも受ける。`-FontSize` と同じ |
| `font` | 書体。`font-family`/`font_family` でも受ける。`-Font` と同じ |

### ヘッダーと引数の両方に書いたとき

**引数が勝つ**。コマンドラインのほうが「その場かぎりの上書き」の意図が強いため。
決め方は上から順に **引数 → ヘッダー → 既定値**。

- **値が食い違うときは警告を出す**(`grid:` と `layout:` の併記と同じ考え方。
  黙って片方を捨てると書き間違いに気づけない)。

  ```
  WARNING: ヘッダーと引数の両方にあり，値が違う．引数を採る: font-size (ヘッダー 26pt / 引数 -FontSize 30pt)
  ```

- **同じ値なら何も言わない**(捨てているものが無いため)。
- **ヘッダーの値は，引数で上書きされる場合でも必ず検査する**。`paper: A2` のような
  書き間違いは、`-Size A0` を付けていてもエラーで止まる。
- 引数を「明示したかどうか」で判断する(`$PSBoundParameters`)。既定値と同じ
  `-Size A0` を明示的に書いた場合も、引数を書いたものとして扱う。
- ヘッダーの値を採ったときは `header : ...` の行で知らせる。

本文の書き方は次のとおり。

- **`# 見出し` が1つの箱**(緑角丸枠)になる。見出しの文字列がそのまま箱の表題になる。
  `# ` より前に書いた内容は捨てられる (表題帯はヘッダーから自動生成するため)。
- 画像は標準の **`![キャプション](file.png)`** で書く。**`[メモ](file.png)` のような
  `!` の付け忘れ**は、拡張子が画像 (`.png`/`.jpg`/`.jpeg`/`.gif`/`.svg`/`.webp`) であれば
  自動で画像として救済される (保険。正式には `![...]` を使う)。
- 画像を横に並べたいときは `::: row` … `:::` で囲む。**画像どうしは空行で区切る**
  (空行が無いと1つの段落・1つの箱にまとまり，横並びにならない)。

### 副題・ロゴ・差し色 (2026-08-31 に追加)

いずれも表題帯まわり。**3つとも省略できる** (書かなければ今までどおりの見た目)。

```yaml
subtitle: "全国24コースの植生調査から"
logo: "images/univ_logo.png"     # リストで複数書ける
accent: "#0b4f9e"                # 枠・見出し帯・表題帯がまとめて変わる
```

- **`subtitle`** は表題のすぐ下に一回り小さく出る。
- **`logo`** は表題帯の**右端に縦中央**で入る。md からの相対パスで書く
  (PDF には `--embed-resources` で埋め込まれるので、配布時に画像を添える必要はない)。
  ロゴを書いたときだけ帯の左右の余白が広がり、**長い表題がロゴに重ならない**。
  大きさを変えたいときはプロジェクト側 `poster.css` で `--logo-max-h` を上書きする。
- **`accent`** は `--box-color` と `--title-bg` の両方を差し替える。
  `#rrggbb`・色名・`rgb(...)` を受け、それ以外の書き方はエラーにする
  (CSS の途中へ差し込むため、閉じ記号を通さない)。
  **枠と表題帯を別の色にしたい**ときは、プロジェクト側 `poster.css` で
  2つの変数を個別に書く。

### 書体を変える

ヘッダーの `font` (または `-Font`) に書く。**`poster.css` の並びの先頭だけが
差し替わる**ので、Mac/Linux 用のフォールバック (Hiragino / Noto / IPAGothic) は
そのまま残る。総称ファミリ (`sans-serif` など) と、自分で並びを書いた場合
(カンマを含む) はそのまま渡し、それ以外は引用符で囲む。

```yaml
font: "Yu Gothic"
```

**指定した書体が実際に埋め込まれたかを検算する**。名前の綴り違いや、その PC に
入っていない書体を指定したときは警告が出る(既定のフォールバックで組まれる)。

```
WARNING: 指定した書体 'No Such Font' が埋め込まれていない．名前が合っているか，その PC に入っているかを確かめる．
```

- **画像の高さは既定で画面高さの30% (`--fig-max-h: 30vh`) までに抑える**。
  箱は中身に応じて自然に伸びる (固定 height なし) ので，これが無いと大きな画像1枚だけで
  箱が伸びきり，後続の箱がページからあふれる (2026-08-29 のフルコンテンツ検証で発見)。
  意図して大きく見せたいときは，プロジェクト側 `poster.css` の `:root` の
  `--fig-max-h` を上書きする (箱ごとの個別上書きは今のところできない)。
- 箇条書きは `- `。表はふつうの pandoc の表記法 (パイプテーブル) が使える。
- 説明文とコード例 (` ``` ` で囲む) を混ぜて書ける。コードは折り返して箱の幅に収まる。
- `<!-- ... -->` の中は PDF に出ない。**採らなかった素材の置き場**に使える。

## 箱の配置 (`layout`) — 省略してよい

**省略すると**、`# ` の出現順に **段組み流し込み** (新聞調。左列を上から埋め，あふれたら右列へ)
になる。まずはこれで書き始めるのがよい。

**見本のように配置を細かく決めたい**ときだけ、ヘッダーに `layout` を足す。
1行が Grid の1行、行の中の要素数がその行の列分割になる (1個だけなら全幅)。
同じ見出し名を複数行に書くと、その行数ぶん縦に結合される (長方形になるように書く)。

```yaml
layout:
  - [OBJECTIVES, CONCLUSIONS]
  - [BACKGROUNDS, RESULTS]
  - [METHODS, RESULTS]
  - [SUMMARY]
```

- `layout` の見出し名は、**本文の `# ` と一字一句 (空白の量以外は) 揃える**。
  揃っていない・本文にあるのに `layout` に無い見出しがあると、pandoc がエラーで止まる
  (取りこぼしたまま PDF ができてしまう事故を防ぐため)。
- `layout` を書いた時点で `-Columns` は無視される (列数は `layout` の行の最大要素数で決まる)。

## 箱の配置を座標で決める (`grid`) — こちらも省略してよい

`layout` の行列表記は「見た目どおりに並べた表」なので原稿を読むだけで配置が分かるが、
**不整形な配置が増えると同じ見出し名を何行にも重ねて書くことになる**。
そういうときは `grid` で **各箱の座標 (`x`・`y`) と大きさ (`w`・`h`) を直に指定できる**
(gridstack.js などのダッシュボード用ライブラリと同じ考え方。2026-08-30 に追加)。

```yaml
grid:
  columns: 2          # 列数 (省略すると 2)
  boxes:
    - {name: OBJECTIVES,       x: 0, y: 0}
    - {name: CONCLUSIONS,      x: 1, y: 0}
    - {name: BACKGROUNDS,      x: 0, y: 1}
    - {name: RESULTS,          x: 1, y: 1, h: 2}   # 縦に2行ぶん
    - {name: METHODS,          x: 0, y: 2}
    - {name: SUMMARY,          x: 0, y: 3, w: 2}   # 横に2列ぶん (全幅)
    - {name: DOMINANT SPECIES, x: 0, y: 4, w: 2}
```

- `x`・`y` は **0 から数える** (左上が `x: 0, y: 0`)。`w`・`h` は省略すると 1。
- 上の例は「箱の配置 (`layout`)」の節の書き方と**同じ配置**になる。
  「RESULTS が2行にまたがる」を，`layout` は同じ名前を2行に書いて表し，
  `grid` は `h: 2` の1箇所で表す。**どちらが読みやすいかは好みで選ぶ**。
- **書き間違いは pandoc がエラーで止める**。箱どうしが同じマスで重なっているとき、
  `x + w` が `columns` を超えて右へはみ出すとき、本文の見出しが `grid.boxes` に
  無い (またはその逆) ときは、名指しで知らせる。
- `grid` と `layout` を**両方書いたときは `grid` が優先**され，**警告が出る**
  (`[warning] ヘッダーに grid: と layout: の両方がある．…`)。
  黙って片方を捨てると書き間違いに気づけないため。使わないほうを消せば警告も消える。

## 段組みの途中で1段組みにしたい箱 (`layout`・`grid` を使わないとき)

`layout` を使わず流し込みのままにしつつ、特定の箱だけ全幅にしたいときは
見出しに `{.full}` を付ける。

```markdown
# SUMMARY of GOLF COURSE {.full}
```

## 用紙サイズと文字の大きさ

- `-Size A0`(既定)/`-Size A1` と `-Orientation portrait`(既定)/`-Orientation landscape` で
  `@page` の実寸 (mm) を切り替える。
- 基準の文字サイズは `-Size` ごとの目安値 (A0=26pt・A1=18pt) を使う。
  **「A4 に印刷しても読める」かどうかは自動検算していない**。実物大で試し刷りするか、
  Chrome で PDF を A4 相当に縮小表示して目視で確かめる運用にする。読みにくければ
  `-FontSize 30pt` のように直接上げる。

## 体裁ファイルの探し方 (プロジェクト側で上書きできる)

`poster.css` と `poster.lua` を、次の順で探して**最初に見つかったもの**を使う。

1. 対象 md と同じディレクトリ
2. その下の `build/`
3. **スキル同梱** (`acposter/.claude/skills/build-poster-pdf/`)

学会・研究室ごとに色 (`--box-color`・`--title-bg`) を変えたいときは、
プロジェクトに `poster.css` を置いて `:root` の値だけ上書きすればよい。

## 段組み崩れの確かめ方 (自動検出はしていない)

初版では「箱がページからあふれていないか」「段組みが重なっていないか」の**自動検出はしない**
(方針として、まずは目視 + `-KeepHtml` 運用に留める)。

- `-KeepHtml` を付けて実行し、`<基幹名>.tmp.html` を Chrome で直接開いて確かめる。
- ページ数が1を超えていたら、内容が用紙サイズを超えてあふれている強いシグナル。
- 崩れる箱だけ `{.full}` を外す／`layout` の行を組み替える／`-FontSize` を下げる、で調整する。

## 姉妹ツールとの行き来 (ggposter / qtposter)

同じ種類のポスターを作るツールが3つある。**置き換えではなく，案件ごとに選ぶ**。

| | 経路 | 原稿の形 | 図の渡し方 |
|---|---|---|---|
| **acposter** (これ) | md → pandoc → Chrome | 散文 (`# ` が箱) | 画像ファイル |
| **ggposter** | R → gtable → PDF | 構造化データ (R list / YAML) | R オブジェクト (ggplot 等) |
| **qtposter** | qmd → Quarto → Typst | 散文 (`# ` が箱) | 画像ファイル |

**本文の書き方は統一できない** (構造化データと散文という根の違い)。そのかわり，
**移し替えのときに書き直さずに済む部分**を2つ揃えてある (2026-08-31)。

- **ヘッダーのキー名は別名で受ける**。3つのツールが同じ意味に使っている名前は，
  どれで書いても通る。

  | 意味 | acposter の正 | 受ける別名 |
  |---|---|---|
  | 副題 | `subtitle` | (無し) |
  | 著者 | `author` | `authors`・`poster-authors` |
  | 所属 | `institute` | `institutes`・`affiliation`・`affiliations` |
  | 注記 | `note` | `funding`・`footer` |
  | 用紙 | `paper` | (無し。`-Size` と同義) |
  | 段数 | `columns` | `cols` |
  | 文字サイズ | `font-size` | `font_size` |
  | 書体 | `font` | `font-family`・`font_family` |
  | ロゴ | `logo` | `logos` |
  | 差し色 | `accent` | (無し) |

  **`size` はどのツールでも別名にしない**。ggposter では用紙，qtposter では文字サイズを
  指しており，黙って取り違えるとポスターが別物になるため。用紙は `paper`，
  文字は `font-size` と書き分ける。

- **`grid:` が「移し替えの共通形」**。acposter と ggposter の `grid:` は
  **完全に同じ書式** (`columns` ＋ `boxes` の `name`/`x`/`y`/`w`/`h`，0 起点，
  `w`/`h` の既定は 1，重なり・はみ出し・名前の不一致はエラー)。配置をそのまま移したい
  ときは `grid:` で書く。
  **`layout:` は移し替えに使えない**。名前は同じでも構造が違う
  (acposter は「行 → 列の割り」の行列，ggposter は「列 → 箱の並び」の名前付きリスト)。
  qtposter には `layout:`・`grid:` のどちらも無い (段送りは `{.break}`)。

3つの比較の全体は `todo/.claude/notes/poster_tools.md` にある。
